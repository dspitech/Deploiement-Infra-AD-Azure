=====================================================================
 ESTIAM - FONCTIONNALITES QUI POURRAIENT ETRE AJOUTEES AU PROJET
=====================================================================

Legende de priorite :
  [P1] = important pour une vraie entreprise (a faire en premier)
  [P2] = utile, apporte un vrai gain
  [P3] = bonus / amelioration de confort

Legende de nature :
  (TF) = a ajouter dans Terraform (ressources Azure)
  (PS) = a ajouter sous forme de script PowerShell (nouveau dossier)
  (DOC) = documentation / organisation


=====================================================================
 1. HAUTE DISPONIBILITE ET RESILIENCE
=====================================================================

[P1] (TF) Second controleur de domaine actif par defaut
     Deja possible (enable_second_dc). Le rendre standard pour ne plus
     avoir de point de defaillance unique.

[P1] (TF) Zones de disponibilite Azure
     Placer SRV-AD01 et DC02 dans des zones differentes (zone 1 / zone 2).

[P2] (TF) Groupe a haute disponibilite (Availability Set)
     Alternative aux zones dans les regions qui n'en ont pas.

[P2] (PS) DFS Namespaces + DFS Replication
     Chemins de partage unifies (\\estiam.local\Partages) et replication
     des fichiers entre deux serveurs de fichiers.

[P2] (PS) Cluster de fichiers ou serveur de fichiers separe
     Sortir le role "fichiers" du controleur de domaine.

[P3] (PS) DHCP en failover
     Utile uniquement en dehors d'Azure (voir limite du DHCP dans Azure).


=====================================================================
 2. SEPARATION DES ROLES (ARCHITECTURE)
=====================================================================

[P1] (TF) Serveur de fichiers dedie (SRV-FILE01)
     Un controleur de domaine ne devrait faire QUE du controle de domaine.
     Deplacer partages, FSRM, shadow copies, impression, IIS.

[P1] (TF) Plusieurs sous-reseaux
     Sous-reseau des DC, des serveurs, des postes, de l'administration.
     Un NSG par sous-reseau avec regles strictes entre eux.

[P2] (TF) Serveur d'administration (jump / bastion interne)
     Poste dedie (PAW) pour administrer AD, au lieu de le faire depuis
     le controleur de domaine.

[P2] (TF) Hub-and-spoke
     Reseau central (hub) + reseaux par usage (spokes), avec peering.

[P3] (TF) Azure Firewall
     Filtrage sortant centralise (URL, categories, journalisation).


=====================================================================
 3. CONNECTIVITE HYBRIDE
=====================================================================

[P1] (TF) VPN Site-a-Site ou ExpressRoute
     Relier le reseau de l'entreprise a Azure.

[P2] (TF) VPN Point-a-Site
     Acces distant des administrateurs sans passer par le portail.

[P2] (TF) DNS prive Azure + resolveur DNS
     Resolution de noms entre reseau local et Azure.

[P3] (TF) Azure Private Link / points de terminaison prives
     Acces prive au Key Vault et au stockage.


=====================================================================
 4. SAUVEGARDE ET REPRISE APRES SINISTRE
=====================================================================

[P1] (TF) Azure Backup + coffre Recovery Services
     Sauvegarde des VM hors de la VM elle-meme, avec retention et
     restauration granulaire. Corrige la limite majeure actuelle (la
     sauvegarde Windows est sur un disque de la meme VM).

[P1] (DOC) Test de restauration planifie et documente
     Restaurer regulierement et consigner le resultat (RUNBOOK).

[P2] (TF) Azure Site Recovery
     Replication des VM vers une autre region (plan de reprise).

[P2] (TF) Verrous de suppression sur les ressources critiques
     Empeche un "terraform destroy" ou une suppression accidentelle.

[P2] (TF) Stockage geo-redondant (GRS) pour les sauvegardes
     Survit a la perte d'une region.

[P3] (PS) Sauvegarde de l'etat AD (System State) exportee vers Azure
     Copie supplementaire hors serveur.


=====================================================================
 5. IDENTITE ET ACCES
=====================================================================

[P1] (DOC/TF) Authentification multifacteur (MFA)
     Via Microsoft Entra ID pour les acces Azure et Bastion.

[P1] (PS) Modele d'administration par niveaux (Tiering 0/1/2)
     Comptes d'administration separes par niveau, interdiction de se
     connecter avec un compte Tier 0 sur un poste ou serveur de tier
     inferieur.

[P2] (PS) Groupe "Protected Users" et politiques de silo d'authentification
     Protege les comptes a privileges (pas de NTLM, Kerberos renforce).

[P2] (TF) Microsoft Entra Connect (synchronisation hybride)
     Synchroniser AD avec Entra ID pour Microsoft 365 et l'authentification
     unique dans le cloud.

[P2] (PS) Politiques de mots de passe granulaires (Fine-Grained)
     Regles plus strictes pour les comptes admin que pour les utilisateurs.

[P2] (PS) Gestion des comptes de service par gMSA
     Remplace svc-backup a mot de passe fixe par un compte a mot de passe
     gere automatiquement par AD.

[P3] (PS) Entra Password Protection (liste de mots de passe interdits)
[P3] (PS) Auto-service de reinitialisation de mot de passe (SSPR)
[P3] (PS) Just-In-Time Access (Azure PIM) pour les roles Azure


=====================================================================
 6. SECURITE RENFORCEE
=====================================================================

[P1] (TF) Microsoft Defender for Cloud (plan serveur)
     Recommandations de securite, detection de menaces, conformite.

[P1] (PS) Durcissement selon les baselines
     Appliquer les baselines Microsoft Security Compliance Toolkit ou
     CIS Benchmark (Windows Server 2022, Windows 11) via GPO.

[P1] (PS) Desactivation de protocoles obsoletes
     SMBv1, NTLMv1, LLMNR, NetBIOS, TLS 1.0/1.1.

[P2] (PS) Signature SMB et LDAP obligatoire (LDAP signing / channel binding)
[P2] (PS) Pare-feu Windows : regles GPO precises par role
[P2] (PS) Pare-feu applicatif / NSG plus fins (ports AD uniquement)
[P2] (TF) Chiffrement des disques par cle geree par le client (CMK)
     Avec Azure Disk Encryption ou Disk Encryption Set + Key Vault.
[P2] (TF) Key Vault en mode RBAC + acces prive uniquement
[P2] (PS) Outils d'evaluation AD : PingCastle / Purple Knight
     Score de sante et de securite de l'annuaire, a rejouer regulierement.
[P3] (PS) Microsoft Defender for Identity (detection d'attaques sur AD)
[P3] (PS) Credential Guard et Device Guard sur les postes
[P3] (PS) Windows Hello for Business
[P3] (PS) Corbeille AD (AD Recycle Bin) activee
     Permet de restaurer un objet supprime par erreur.

     VM arretee, echecs de connexion en rafale.

[P2] (PS) Rapport quotidien / hebdomadaire envoye par e-mail
     (comptes inactifs, verrouillages, membres des groupes privilegies).

[P3] (TF) Tableau de bord Azure (Azure Dashboard / Workbook)

=====================================================================
 16. PLAN D'EVOLUTION SUGGERE
=====================================================================

 Phase 1 - Fondations solides  (priorite P1, quelques jours)
   - .gitignore + CI/CD avec validate/plan
   - Second DC actif + zones de disponibilite
   - Azure Backup (coffre Recovery Services)
   - Log Analytics + alertes de base
   - Serveur de fichiers separe du controleur de domaine
   - Arret automatique des VM (cout)

 Phase 2 - Securite et gouvernance  (P1/P2)
   - Baselines de securite (CIS / Microsoft), protocoles obsoletes
   - Defender for Cloud, PingCastle, Corbeille AD
   - Tiering d'administration, gMSA, Protected Users
   - WSUS ou Azure Update Manager
   - Sous-reseaux segmentes + NSG par sous-reseau

 Phase 3 - Hybride et industrialisation  (P2/P3)
   - VPN, Entra Connect, MFA
   - PKI interne, LDAPS
   - DSC/Ansible, tests Pester, PSScriptAnalyzer
   - Sentinel, rapports automatiques, import RH
